# Claude Code guidance

First, work out which of two situations you're in by running
`git remote get-url origin`:

## This checkout IS the template (`appspan/local-only-pwa-template`)

The user wants to build their own app from it. Read `docs/setup-prompt.md`
and follow it as if the user had pasted it. Before doing anything else, ask
for the four values at the top of that prompt (app name, short name, repo
name, git identity). Create their new repo in the **parent** directory of
this checkout, never inside it, and do all further work in the new repo.
Do not modify this template checkout unless the user explicitly says they
are improving the template itself.

## This checkout is an app built from the template (any other remote)

Follow `docs/ship-runbook.md` for every change, and use the `ship-change`
skill if your session lists it. If setup looks incomplete (placeholder
name "My App" still in `template.config.json`, no Vercel link, or
`productionUrl` still `https://example.com`), offer to run the remaining
steps of `docs/setup-prompt.md` before making feature changes.

## Always

- `public/` is served as-is. There is no build. `public/build.json` is
  generated by `npm run stamp` and is gitignored; never edit or commit it.
- All user state stays on the device. Storage goes through `LocalState`
  (`public/local-state.js`); sharing goes through the URL fragment
  (`public/share-link.js`). Do not add a backend, analytics, or any
  request to a third party without the user asking for it by name.
- New or renamed core files go in the `CORE` list in
  `public/service-worker.js`; bump `CACHE` when that list changes.
- Every release appends an entry to `public/app-changes.json` in the same
  commit, written for the app's users.
- `npm test` must pass before any commit. It also checks that
  `template.config.json`, `index.html`, and both manifests agree.
